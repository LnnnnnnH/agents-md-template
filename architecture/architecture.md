# 架构

用途：说明系统怎么拆、数据怎么走、哪些边界不能破。
何时阅读：改结构、跨模块行为，或需要判断改动该落在哪一层时。

## 规则

- 画清模块职责和依赖方向，不要写成文件清单（文件清单在 `project/repo-map.md`）。
- 不变量是改动时不得破坏的约束，必须写可检查的句子。
- 决策的「为什么」写在 `architecture/decisions.md`，这里只写当前结构。
